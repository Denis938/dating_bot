## 2. Технологии из системы оценивания: файлы и применение

### П.1 — Рейтинг (три уровня)

| Уровень | Что сделано | Файлы |
|---------|-------------|-------|
| **Уровень 1 (первичный)** | Полнота анкеты, число фото, наличие описания → `primary_score`; фильтрация ленты по полу, возрасту, городу из `preferences` | `bot/ranking.py` (`calculate_primary_score`), `bot/profile_helpers.py`, `bot/handlers.py` (`_load_profiles_to_cache`) |
| **Уровень 2 (поведенческий)** | Соотношение лайков к просмотрам, число мэтчей, активность (исходящие лайки) → `behavioral_score` | `bot/ranking.py` (`calculate_behavioral_score`), таблица `interactions` в `bot/database.py` |
| **Уровень 3 (комбинированный)** | Взвешенная сумма: 40% первичный + 60% поведенческий; сортировка ленты по `combined_score` | `bot/ranking.py` (`PRIMARY_WEIGHT`, `BEHAVIORAL_WEIGHT`, `recalculate_rating`), таблица `ratings` |

**Не реализовано (заявлено в ТЗ, но в коде нет):** реферальная система (уровень 3); инициация диалогов и активность по времени суток (уровень 2, п.4).

**Доп. баллы по ТЗ:** рейтинги в отдельной таблице `ratings` + периодический пересчёт через Celery Beat — **да**.

### П.2 — Redis (0–2 балла)

**Применение 1 — кэш ленты анкет:** при просмотре подгружается до 10 профилей в список `profiles:{user_id}`; выдача через `LPOP`, TTL 300 с; при обновлении анкеты/лайке — инвалидация.

- `bot/redis_cache.py` — класс `ProfileCache`
- `bot/handlers.py` — `view_profiles`, `_load_profiles_to_cache`, `invalidate` / `invalidate_all`

**Применение 2 — backend результатов Celery:** `backend=config.redis_url` в `bot/tasks.py`.

*Не только для Celery:* кэш анкет — отдельное обоснованное применение.

---

### П.3 — Celery (0–2 балла)

- Периодическая задача `recalculate_all_ratings_task` (Beat, каждые 1800 с)
- Пересчёт всех пользователей через `ranking.recalculate_rating`
- Файлы: `bot/tasks.py`, `docker-compose.yml`

Без Celery пересчёт всех рейтингов по расписанию блокировал бы бота или требовал бы отдельного cron-скрипта.

---

### П.4 — MQ-брокер / RabbitMQ (0–2 балла)

**Событийная шина (не только Celery):** topic-exchange `dating_events`, routing keys `profile.updated`, `interaction.*`, `match.created`.

- Публикация: `bot/mq.py` (`EventPublisher`), вызовы из `bot/handlers.py` (лайк, пропуск, мэтч, обновление профиля)
- Потребление: `bot/main.py` — `EventConsumer` пересчитывает рейтинг затронутых пользователей при событиях

Celery использует тот же RabbitMQ как broker (`bot/tasks.py`).

### П.5 — Метрики и логирование (0–2 балла)

**Метрики (Prometheus):**
- Счётчики: регистрации, лайки, мэтчи — `bot/metrics.py`, инкремент в `bot/handlers.py`
- HTTP endpoint `:8000/metrics` — `start_metrics_server` в `bot/main.py`
- Сбор: `prometheus.yml`, сервис `prometheus` в `docker-compose.yml`

**Логирование:** стандартный `logging` с уровнем INFO, контекст в сообщениях (user_id, ошибки MQ/S3) — `bot/main.py`, `bot/handlers.py`, `bot/tasks.py`.

*Замечание:* гистограмма `MESSAGE_PROCESSING_TIME` объявлена, но пока не обёрнута вокруг обработчиков (можно доработать).

## 3. Дополнительный функционал (сверх минимума этапа 4)

1. **Мгновенный пересчёт рейтинга по событиям MQ** — не только по расписанию Celery (`bot/main.py` + `bot/mq.py`).
2. **Загрузка и показ фото в карточке анкеты** через MinIO и presigned URL (`bot/s3_service.py`, `bot/handlers.py`).
3. **Graceful degradation** — при недоступности Redis/RabbitMQ бот продолжает работу без кэша/MQ (`bot/main.py`).
4. **Настройки поиска** — пол, возраст, город (`preferences`, `bot/handlers.py`).
5. **Практические задания** в репозитории: `tasks/task1` (SQL), `tasks/task2` (бенчмарк MQ).
